Consensus · references · when a result misses

Wrong result → better search

Not “report a bad paper”. The click is a researcher saying this isn’t what I’m looking for, and the useful reply is a better search, not a receipt. Four ways to catch that and turn it into progress. Nothing in any of them deletes, strikes through, or removes a paper. The earlier flag did, and that is precisely what made it feel risky to press.

  1. Ask the goal, not the fault. “What were you hoping to find?” is friendlier than “what’s wrong with this?”, and it is a better signal: you learn the target, not just the miss.
  2. Nothing disappears. Set aside, reversible, always. No strikethrough anywhere.
  3. Make it pay the user now. Tidying a result set is useful to them; filing a report is a chore for us. Feedback that does something for the user is not scary to press.
  4. Scale the response to the evidence. One miss in twenty is normal. Three is a pattern, and only then is it fair to suggest a different angle.
  5. Suggest, never fire. The new query arrives pre-filled and editable; nothing runs without a press.
  6. Offer both scopes. Search this thread, or start a new chat. The user knows which one they need; we do not.
  7. Silence is already data. Someone who searches again and keeps nothing has told you the results missed. That signal is free, it is bigger than any button, and it is the reason not to over-build the button.

D · Offer the narrower search

skips the question entirely

Asks nothing. The card offers the two or three narrowings that would have excluded this paper, each with its cost shown: would drop 2 of 6, keep 4. The user picks an outcome instead of describing a problem, and we learn the same thing from which one they pick.

Where I would land: B as the default gesture and A as what happens when the user wants to say more. They compose cleanly, because B’s nudge can open exactly A’s goal question. That gives you a one-click action with no fear attached, a proportionate response to the one-bad-many-good case, and a real redirect when the evidence justifies one. C is worth running alongside either, since it costs nothing on the result list and catches the silent majority. D is the one to test rather than assume: it is the fastest, but it only works when the system’s guess about the narrowing is right.
